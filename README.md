# 억제적 통제 검사

중·고등 발달장애학생의 **억제적 통제**를 재는 웹 검사입니다. 결과는 교사와 작업치료사가 집행기능 지도·치료 자료로 씁니다.

기존 고/노고 검사는 흥미 요소가 없어서 학생이 과제에 붙어 있지 못하고, 그래서 나온 숫자가 실제 억제 능력이 아니라 "집중하지 않은 상태"를 재게 됩니다. 이 도구는 두 가지로 그걸 다룹니다 — 학생별로 바꿔 끼우는 테마와 수집 보상으로 **끝까지 하게 만들고**, 결과가 믿을 만한 상태가 아니면 **숫자를 능력으로 읽지 말라고 화면이 먼저 말합니다.**

설계 문서는 [docs/superpowers/specs/](docs/superpowers/specs/2026-10-21-inhibitory-control-test-design.md)에 있습니다.

---

## 교사용 한 장 안내

학생이 보는 화면에는 **글을 한 줄도 쓰지 않습니다** — 글을 못 읽는 학생도 혼자 할 수 있어야 하기 때문입니다. 그래서 아래 내용은 화면이 스스로 설명할 수 없습니다. 쓰시기 전에 한 번 읽어 주세요.

### 검사를 멈추거나 난이도를 바꾸려면: 화면 구석 아이콘을 1초 길게 누릅니다

검사 중에는 화면 구석에 흐린 아이콘이 하나 있습니다. **1초 이상 길게 누르면** 교사용 안내가 열립니다. 짧게 누르면 아무 일도 일어나지 않습니다 — 학생이 우연히 누르지 못하게 일부러 그렇게 했습니다.

그 제스처로 할 수 있는 것:

- 검사 중단
- 연습이 끝난 뒤 난이도를 추천값과 다르게 고르기
- 연습으로도 규칙을 못 잡았을 때의 안내 보기

**기기가 하나이고 선생님이 자리를 비우기 때문에**, 학생이 보면 안 되는 것은 화면을 나누는 것으로 분리할 수 없습니다. 그래서 전부 이 제스처 뒤에 있습니다. 선생님이 자리에 없으면 검사는 추천값으로 자동 진행됩니다.

### 운용

1. 설정 화면에서 학생 별칭, 테마, 검사 길이를 고릅니다. **실명 대신 별칭을 쓰세요** — 학교 공용 기기는 여러 학생이 돌아가며 씁니다.
2. "시작"을 누르면 연습 8문항이 돌고, 그 결과로 난이도가 추천됩니다.
3. **시작을 누른 뒤에는 자리를 비우셔도 됩니다.** 그 뒤부터 끝까지 학생 혼자 진행합니다.
4. 끝나면 결과 화면이 뜹니다.

같은 학생을 반복 검사할 때는 **"지난 설정으로 바로 시작"** 한 번이면 됩니다.

### 결과 화면의 배지를 먼저 보세요

맨 위 배지가 **이 결과를 해석해도 되는지**를 알려줍니다. 이 도구가 있는 이유가 그것입니다.

| 배지 | 뜻 |
|---|---|
| **양호** | 수치를 그대로 읽어도 됩니다. |
| **해석 주의** | 조급 반응이 많거나 중간에 이탈한 구간이 있습니다. 이유를 확인한 뒤 읽으세요. |
| **억제 지표 참고용** | 참아야 할 문항이 너무 적었습니다. 억제 수치는 참고로만 보세요. 검사 길이를 늘리면 해결됩니다. |
| **해석 불가** | 과제에 참여하지 않은 회차입니다. **이 숫자로 학생을 판단하지 마세요.** |

그리고 **"억제 실패"와 "누락"은 다른 문제입니다.** 참아야 할 때 누른 것(억제 실패)은 억제력, 눌러야 할 때 안 누른 것(누락)은 주의력입니다. 합쳐서 "오반응"으로 읽으면 지도 방향이 반대로 갑니다.

### 기록을 주기적으로 내보내세요

**결과는 검사한 기기의 브라우저에만 저장됩니다.** 서버로 보내지 않습니다. 그래서:

- **브라우저 데이터를 지우면 전부 사라집니다.**
- 회차별 추이는 **같은 기기에서** 반복 검사했을 때만 쌓입니다.
- 기록·이력 보기 화면에서 **복원용 JSON 백업**을 주기적으로 내려받아 두세요. 분석용 CSV도 거기서 받습니다.

PIN을 켜면 다른 학생이 이름과 결과를 우연히 보는 것을 막을 수 있습니다. 다만 **PIN을 잊으면 이 앱에서는 기록을 열 수 없습니다** — 켜기 전에 백업을 받아 두세요. 켜는 화면에 그 안내와 백업 버튼이 함께 있습니다.

### 이 도구가 보장하는 범위

스마트폰은 기기마다 터치 지연이 다릅니다. 그래서 비교할 수 있는 것은 **같은 학생이 같은 기기에서 반복 측정한 회차 사이**입니다. 다른 기기에서 잰 반응시간의 절대값은 직접 비교하지 마세요 — 추이 그래프에 다른 기기 회차가 섞이면 화면이 알려줍니다.

난이도 단계가 다른 회차의 수치도 나란히 놓지 마세요. "좋아진 것"과 "쉬운 단계로 내려간 것"이 구별되지 않습니다. 추이 그래프는 같은 단계끼리만 그립니다.

## 기술

빌드 단계가 없는 정적 웹앱입니다. 바닐라 JavaScript ES 모듈, 프레임워크 없음, 런타임 의존성 없음. 브라우저가 `index.html`과 `js/*.js`를 그대로 읽습니다.

```
js/              순수 로직 — 설정 상수, 문항 순서, 지표 계산, 배지 판정,
                 연습 추천, 해석 문장, 테마, 저장, 내보내기, 타이밍 엔진
js/screens/      화면 — 설정, 연습, 검사, 결과, 이력 (+ 공유 문항 진행기)
sw.js            오프라인 캐시
```

### 개발

```bash
npm install
npm test
```

Vitest와 jsdom은 **테스트 전용**이고 배포되지 않습니다. 테스트 1,129개.

### 배포

**HTTPS가 필요합니다** — 서비스 워커가 보안 컨텍스트에서만 동작합니다. 비보안 http에서도 앱은 뜨지만 오프라인이 되지 않습니다.

파일을 바꿔 배포할 때마다 **`js/config.js`와 `sw.js`의 `TOOL_VERSION`을 둘 다 올려야 합니다.** 올리지 않으면 기기가 캐시된 옛 파일을 계속 씁니다 — 고친 줄 알지만 기기는 예전 그대로입니다. 두 값이 서로 어긋나는 것은 테스트가 잡지만, 둘 다 안 올린 것은 잡을 수 없습니다(빌드 단계가 없어서 내용 해시를 쓸 수 없습니다).

**배포한 뒤 오프라인을 한 번 확인하세요.** 앱을 열고, 네트워크를 끊고, 새로고침해서 그대로 열리는지 보세요. 서비스 워커 등록 실패는 일부러 조용히 넘기므로(등록이 안 돼도 검사는 되어야 하니까) 확인하지 않으면 모릅니다.

배포 절차의 자세한 내용은 설계 문서 §6-1에 있습니다.

### 쓰기 전에 실기기에서 확인해야 할 것

코드로는 확인할 수 없고 쓰실 기기에서 눌러봐야 하는 것들입니다. 설계 문서 §7에 있습니다.

- 터치로 **소리가 실제로 나는지** (브라우저가 제스처 안에서만 오디오를 허용하고, 그 시점이 기기·OS 버전마다 다릅니다)
- 화면 하단 절반이 **브라우저 도구 모음에 가리지 않는지** (구형 iOS)
- 테마 6종의 3단계 난이도가 **서로 비슷한지** (이모지 쌍의 지각 난이도는 추론으로 맞출 수 없습니다)
- 결과 화면의 **해석 문장을 작업치료 전문가가 검토**했는지 — 검토 전에는 화면에 "검토 전 초안"으로 표시됩니다
- §5.8의 판정 기준값(0.2초, 20%, 40%, 8문항)에 **문헌 근거**를 붙였는지 — 현재는 임시값이고 한 곳에 모여 있습니다
